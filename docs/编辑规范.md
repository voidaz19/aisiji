#### 1. 光标在节点 B 开头（`pos = 0`）按 `Backspace`（向上退格）

* **1.1 B 有前置同级兄弟节点 A**：
  
  * 若 B **无子节点**：
    * B 有文字：把 B 的文字追加合并到 A 末尾，删除 B，**光标停在拼接缝隙处**。
    * B 无文字：删除 B，光标停在当前可见顺序的上一个节点末尾；若 A 的子树已展开，则落在 A 最深的可见后代节点末尾，若 A 的子树已折叠，则落在 A 末尾。
  * 若 B **有子节点**：**禁止合并/删除，触发 B 自身及其子节点抖动提示**。

* **1.2 B 是普通内容父节点 P 的第一个子节点**：
  
  * 若 B **无子节点**：
    * B 有文字：把 B 的文字合并到 P 末尾，删除 B，光标落在 P 末尾。
    * B 无文字：删除 B，光标落在 P 末尾；**P 节点下方不留存任何虚节点 (Ghost Node)**。
  * 若 B **有子节点**：**禁止合并/删除，触发 B 自身及其子节点抖动提示**。

* **1.3 B 是 Date 日期节点（或根视图）下的第一个子节点**：
  
  * 若 B **有文字**：**禁止合并，触发 B 自身抖动提示**（提示上方为日期标题无法合并）。
  * 若 B **无文字（空行）**：
    * 若后方有兄弟节点：删除 B，光标精准跳到下一个兄弟节点的**开头**（`pos = 0`）。
    * 若 B 是日期下唯一的节点：删除 B，留存一个虚节点 (Ghost Node)，**光标直接聚焦在虚节点上**。

* * *

#### 2. 光标在节点 A 最末尾（`pos = 文本长度`）按 `Delete`（向后删除）

* 若后方有**无子节点**的兄弟 B：合并 B 的文字到 A 末尾，删除 B，**光标精准定位在 A 原末尾（拼接缝隙处）**。
* 若后方有**带子节点**的兄弟 B：**禁止合并，触发 A 自身抖动提示**。
* 若后方**无兄弟节点**（A 已是最后一个节点）：**禁止操作，触发 A 自身抖动提示**。

* * *

#### 3. 选区删除与显式整行删除

* **指针拖动升级为节点选择**：
  * 指针保持在起始节点的逻辑布局边界内时，由编辑器继续处理普通文本选择。
  * 指针从左侧或右侧越过起始节点的逻辑布局边界时，即使仍位于同一行，也升级为当前节点的单节点选择。
  * 进入节点选择模式后，页面左右画布均按纵向位置命中最近节点；指针可在任一侧继续上下拖动以扩展连续节点范围。
  * 从可编辑内容开始的拖动在松手前属于可逆预览：进入节点选择时隐藏但保留编辑器逻辑选区；拖回起始节点布局时撤销节点预览并恢复文字选区。
  * 仅在节点选择预览中松手时，才正式清理文字选区并由页面画布接管焦点；在文字选择状态松手则保留编辑器选区和焦点。
  * 节点布局边界使用树行的层级缩进、节点对象起点和右侧内边距计算，不依赖文本宽度、空内容或 Markdown 组件尺寸。
* **Shift+上/下扩展选区**：
  * 文本选区的活动端未到当前节点边界时，由编辑器继续扩展文本选区。
  * 活动端到达边界后继续向外扩展时，先升级为当前节点单独选中；再次继续扩展时才加入相邻节点。
  * 节点范围选区存在时，单按不带修饰键的方向键退出节点选择模式，并把焦点留在选区活动节点；Shift+方向键继续扩展选区。
* **离散节点选择**：
  * `Ctrl+点击`（macOS 使用 `Cmd+点击`）逐项加入或移出节点选区，允许选中不连续节点；选中父节点仍连带整棵子树。
  * 离散选区与连续拖拽选区共用复制、剪切、删除和结构操作；普通无修饰键点击仍退出现有节点选区并回到文字编辑。
* **节点选区缩进与提升**：
  * 节点范围选区存在时，`Tab` 对选中的子树根执行批量缩进，不清除选区。
  * 每个选中根寻找操作前同级列表中最近的未选中前置节点作为父节点；连续选中的同级根共享同一目标，并按原顺序追加到目标已有子节点之后。
  * 没有可用前置同级节点的根保持原位，不阻止其他可缩进根执行。父节点及其已连带选中的后代只移动一次。
  * `Shift+Tab` 把选中的子树根分别提升一级；同一父节点下保持原顺序，已处于当前页面边界的根保持原位，不阻止其他可提升根执行，操作后同样保留选区。
* **选区删除（如 `Cmd+A` 全选文本）**：
  * 按 `Backspace` 第一下仅清空选中的文本（节点保留为空行）；按第二下 `Backspace` 才触发上述“空行退格”规则。
* **显式整行删除（如快捷键 `Cmd+Shift+Backspace` 或点击删除按钮）**：
  * 无条件将该节点及其**整个子树**一起移入回收站；删除后光标平滑转移到相邻节点（优先级：`上一个兄弟 > 下一个兄弟 > 父节点`）。

#### 4. 根视图编辑

* 普通内容节点进入根视图后仍使用与树内节点相同的编辑器，可正常编辑文本、使用 Markdown、选区和输入法。
* 日期节点与全局根仅作为结构容器展示，不提供内容编辑器。
* 根节点按 `Enter` 时保持当前视图根不变，并把光标后的文本拆分为根节点的子节点；在末尾按 `Enter` 即在其下方创建一个空子节点。
* 根节点开头按 `Backspace` 或末尾按 `Delete` 时禁止跨越根视图边界，保持当前视图根不变，并静默拦截操作。
* 仅显式整行删除根节点时，当前视图根才迁移到删除后的焦点节点，不得指向已删除节点。

#### 5. 连续可编辑画布

* 节点仍是拥有独立 ID、Markdown 和树操作边界的原子编辑单元；页面级连续画布只负责把空白点击协调到正确的编辑器。
* `今天` 与 `所有笔记` 的页面内容区显示文本光标，并把空白点击投影到最近的真实光标位置：同一视觉行左侧落到该行开头，右侧落到该行末尾，多行节点按点击所在视觉行计算；标题与第一行之间按纵向距离选择最近编辑器。
* 只有最后一个树块下方的页面空白按当前页面 `rootId` 聚焦页面级虚节点，单击不创建实体节点，开始输入或按 `Enter` 时才实体化。
* 虚节点在数据层是临时 `DraftNode` 插入位，不拥有稳定节点 ID，不写入工作区、操作日志或同步协议；在编辑层必须与真实空节点共用同一套编辑器命令入口。
* 需要真实节点身份的命令（缩进、提升、附件、节点链接、字段等）使用统一草稿命令入口；具备适用条件的命令必须先按真实业务规则预检，确认命令可执行后才实体化，新增命令不得在 `GhostEditor` 中另写一套实体化规则。
* `Tab`/`Shift+Tab` 先使用与真实节点相同的树移动命令预检；无法缩进或已到当前页面根边界时保持虚节点，不创建空节点。可执行时才创建空节点，待真实节点行完成挂载并建立稳定布局基线后执行缩进/提升，以沿用普通节点的结构动画。
* 虚节点选择“插入文件”时先打开系统文件选择器；取消或未选择文件时保持虚节点。确认至少一个文件后才实体化一次，并把附件任务交给替换它的真实编辑器，继续复用普通节点的稳定占位、顺序保持、错误状态和失败项重试，不得因交接重复创建节点或附件引用。
* 真实节点缩进到空父节点、取代其虚占位行时，占位行的增删不得阻断前后稳定真实节点的布局动画。
* 普通空节点按 `Enter` 时保留当前节点，并在其视觉下方创建、聚焦新的空节点；只有非空节点在行首按 `Enter` 才会创建上方空节点。
* 点击节点链接、外链、附件、折叠按钮、圆点、层级线操作或编辑器内部时，不得被页面级画布处理器抢占。
* 搜索页与回收站保持只读，不启用连续可编辑画布。

#### 6. 统一输入与插入语义（按键待定）

本节只定义用户意图和结果，不锁定具体按键。一个语义命令以后可以同时由命令菜单、工具按钮、快捷键、拖放或粘贴触发。

* **菜单入口**：编辑器应提供统一的插入/操作菜单。菜单可用“格式、结构、节点、文件、后续扩展”等功能分组帮助浏览，也支持直接按名称或别名过滤；分组只是整理菜单，不要求用户先选择分类。菜单的具体触发方式留待交互细节阶段确定。
* **格式命令**：粗体、斜体、删除线、高亮、行内代码、标题、引用和待办等命令复用现有 Markdown 语义。有选区时作用于选区，无选区时插入可继续编辑的成对结构或前缀；每次意图形成一个可撤销操作。
* **节点命令**：节点链接、嵌入节点、创建子节点等命令使用标题或路径选择，不要求用户记忆稳定 ID；稳定 ID 只写入 Markdown 或节点关系数据。
* **文件入口**：菜单只提供一个“插入文件”入口，允许一次选择一个或多个文件，不按图片、音频、视频、PDF 或其他附件拆成多个按钮。文件选择、拖放和剪贴板文件统一进入附件插入流程；选择完成后由 MIME 类型和扩展名自动决定图片、音频、视频、PDF、文本预览或普通文件项，不因入口不同而产生不同附件记录或渲染结果。只有未来出现“录音”“拍照”等不同采集流程时，才增加独立动作。
* **网址粘贴**：选中文字后粘贴网址，补全为普通链接；无选区粘贴网址，按安全协议和资源类型判断为普通链接或远程图片；不能安全识别时保留原始文本。
* **文本粘贴**：纯文本继续按现有多行粘贴规则创建节点；粘贴内容中的 Markdown 不被强制改写。文件剪贴板项优先走附件流程，不把二进制内容当作文本插入。

**当前第一阶段入口**

* 普通节点和可编辑页面根节点在编辑器末端显示一个 `+` 按钮；菜单支持搜索，首批提供粗体、斜体、删除线、高亮、行内代码、标题、引用、待办、分隔线、节点链接和插入文件。
* 单独按下并松开 `Ctrl` 也会打开统一输入菜单，菜单锚定当前光标附近；下方空间不足时显示在光标上方，靠近左右边缘时自动收进视口。菜单位于光标下方时固定靠近光标的顶边，位于光标上方时固定靠近光标的底边；筛选导致菜单高度变化时沿锚点方向收缩，不得在菜单与光标之间留下空白。菜单已打开时再次单独松开 `Ctrl` 关闭菜单。
* `Ctrl+B`、`Ctrl+Z`、`Ctrl+C` 等组合键优先执行编辑器原有快捷键，不触发统一输入菜单；按住 `Ctrl` 期间出现其他按键、指针点击、窗口失焦或输入法 composing 时取消菜单触发。
* 菜单打开后搜索框自动聚焦，可直接输入名称或别名；`ArrowUp`/`ArrowDown` 循环选择，`Enter` 执行当前项，`Esc` 关闭。点击 `+` 时菜单从按钮附近打开。
* 文件菜单只有一个“插入文件”动作，系统文件选择器不设置类型白名单并允许多选；从剪贴板粘贴文件或把文件拖到编辑器时复用同一插入函数。
* 文件处理期间在原选区末端显示临时占位；占位范围随后续文档变化映射，处理完成后仍在原意图位置替换选区。多个文件并行保存，但 Markdown 始终按用户选择顺序生成。
* 文件全部失败时移除临时占位并保留原选区文本；菜单显示首个错误原因和“重试”。部分成功时先按原顺序插入成功项，只对失败项提供重试。
* 菜单的键盘触发方式和网址智能粘贴仍待后续确认；本阶段不新增快捷键。

**选区菜单**

* 行内文本拖选结束并提交非空选区后，在选区附近显示紧凑工具栏，拖动过程中不得提前显示；工具栏提供粗体、斜体、删除线、高亮、行内代码、复制和剪切，命令继续复用统一 Markdown 命令，保持源码选区和撤销语义。
* 节点连续选区在拖动结束并提交后显示节点工具栏，拖动预览阶段不得显示；`Ctrl/Cmd+点击`离散选择与键盘选择不经过拖动，选区形成后可立即显示。工具栏提供复制、剪切、批量缩进、批量提升和删除，结构操作复用节点选区已有命令并保留选区。
* 两类选区菜单默认显示在选区对象上方，顶部空间不足时自动翻到下方；行内文本菜单相对选区居中，节点菜单与选中节点对象左边缘对齐，并在靠近视口边缘时收进可见范围。
* 节点“复制”按当前可见顺序把所选节点导出为纯文本，后代相对最浅选中层级使用两个空格缩进；“剪切”必须先成功写入同样的剪贴板文本，再把可删除的选中内容子树移入回收站，复制失败时不得删除。
* 复制成功显示短暂的“已复制”状态；批量缩进和提升分别反馈成功或不可执行。选区菜单自身的指针与点击事件不得触发画布清空选区或提交点击抑制。
* 选区菜单按钮不会抢走原选区焦点；节点选区预览期间隐藏行内文本工具栏，打开节点末端 `+` 菜单时隐藏行内选区工具栏，避免多个操作层重叠。

**附件插入事务**

1. 在光标位置预留一个稳定的附件占位项，立即显示文件名、大小和处理中状态，光标不跳离当前位置。
2. 附件登记、文件复制/哈希和 Markdown 引用必须作为同一项插入意图处理；处理中失败不得留下不可解析的 `attachment://` 引用。
3. 成功后占位项原地转换为现有附件原子组件；多文件按用户选择顺序插入，顺序不得因完成速度改变。
4. 失败时移除临时占位、保留原选区文本，并提供错误原因和重试入口；重试不得重复创建已经成功的附件引用。
5. 关闭文件选择器且未选择文件时不得产生变化；未来如增加处理中止能力，应清理临时文件和临时记录。已完成附件的删除继续遵循回收站与引用清理规则。

**编辑反馈与撤销**

* 处理中、成功、失败和取消是可观察状态；状态变化不得造成节点高度无故跳动，预览区域沿用稳定占位尺寸。
* 附件、链接、节点链接和待办在编辑器内作为原子内容单元处理。方向键可跨过，退格/删除优先整体处理，避免删掉半段 Markdown 控制符。
* 一次用户意图只产生一个可理解的文本撤销单元，上传完成后的多文件 Markdown 由一次事务写入，不额外拆成多个撤销步骤。撤销时同步清理无引用附件记录仍是后续附件生命周期工作，本阶段不伪装为已完成。
* 所有入口都必须保留源码模式和原始 Markdown 的可恢复性；Live Preview 只改变显示，不改变持久化格式。

**未来 Supertag 扩展边界**

* 统一命令菜单预留“Supertag、字段、关系”类别，但当前不定义具体按键或数据格式。
* `insertAttachment`、`insertNodeLink`、`applySupertag`、`insertField` 等属于不同语义命令；它们可以共享菜单和候选选择器，但不能把附件元数据塞入 Supertag 或 Markdown 文本之外的隐式状态。
* Supertag 字段若引用附件，应复用附件原子组件和同一套打开、折叠、删除语义；字段值的持久化归节点模型，二进制文件身份仍归附件记录。

**验收标准**

* 用户不记得 Markdown 语法时，仍能通过可发现的入口完成格式、节点链接和文件插入。
* 用户熟悉 Markdown 时，直接输入仍保持连续、可预测、可撤销，不被过早预览打断。
* 拖放、粘贴和文件选择的结果一致；失败、取消、重试和撤销都不留下悬空引用。
* 新增命令不需要改变已有节点 ID、Markdown、附件记录、操作日志或同步协议。
