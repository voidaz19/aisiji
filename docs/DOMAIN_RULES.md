# 节点领域规则

本文记录节点笔记当前确认的底层行为语义。它描述用户操作应该产生的数据结果，
不规定 React、Zustand、数据库或同步的具体实现。

当实现与本文冲突时，应先确认产品语义，再修改实现或本文。新增行为应优先补充
操作前后示例和自动测试。

## 模型原则

- 节点具有稳定身份。修改文字、移动、缩进、添加标签不会产生新身份。
- 每个节点只有一个真实父节点和一个真实位置。
- 搜索、日期、supertag 和引用可以在其他视图展示节点，但不会产生第二个真实父节点。
- 引用指向同一节点；复制会创建新的节点身份。
- 工作区根是虚拟容器，不是可以编辑、删除或链接的普通节点。
- 树中不允许出现环、无效父节点或不可见孤儿。
- 一次用户意图必须原子完成，不能留下部分修改。
- 焦点、光标、折叠、抖动和动画属于交互状态，不是节点内容。

## 操作层次

节点操作分为三个层次：

1. 交互层根据光标、折叠和选择状态解释用户意图。
2. 领域命令明确描述内容、目标位置和操作范围。
3. 原子事务一次完成创建、修改、移动、删除等实际变化。

例如，拆分节点是一个领域命令，但内部会同时修改原节点、创建新节点并设置位置。
创建子节点和创建同级节点在底层都是“在明确位置创建节点”。缩进、提升和拖拽
在底层都是“移动整棵子树”。

## 树与编辑

### 拆分

- 没有展开子树的普通节点在光标处拆分时，前半部分保留原身份，后半部分成为紧随其后的同级新节点。
- 有可见子节点的展开节点拆分时，后半部分成为第一个子节点，原有子节点依次排在其后。
- 有隐藏子节点的折叠节点拆分时，后半部分成为同级新节点；原有子节点继续隐藏在原节点下。
- 拆分位置由交互层在操作发生时明确确定。持久化结果不依赖之后的折叠状态重新推断。

### 合并

- 在节点开头向前合并时，当前文字追加到前一个同级节点，前一个节点保留身份。
- 第一个子节点可以向普通父节点合并。
- 当前节点有子节点时拒绝向前合并，并由界面执行抖动反馈。
- 在节点末尾向后合并时，后一个同级节点的文字追加到当前节点。
- 后一个节点有子节点时拒绝向后合并，并由界面执行抖动反馈。
- 被合并节点保留“已合并到目标节点”的身份转向，使旧链接仍能找到内容；撤销时可恢复原身份。

### 缩进、提升与拖拽

- 缩进使节点成为前一个同级节点的最后一个子节点。
- 提升使节点成为原父节点之后的同级节点。
- 移动节点时整棵子树一起移动，后代层级保持不变。
- 禁止把节点移动到自己的后代中。
- 拖拽表示把整棵子树插入两个可见节点之间的明确插槽，不存在“放到节点中央成为子节点”的目标区域。
- 同一段子树末尾的可用层级按从深到浅排列为多个纵向插槽；鼠标继续向下时逐级退出，横向位置不参与层级判断。
- 插入线必须同时显示最终位置和最终层级，放下后的数据结果不得再根据鼠标位置重新推断。
- 折叠只改变可见性，但可以作为交互层解释 Enter 行为的上下文。

## 选择与删除

- 选中父节点在语义上等于选中它的整棵子树，所有后代应连带显示为选中。
- 多选结果先规整为互不包含的顶层节点，避免重复处理同一后代。
- 单独通过 Backspace、Delete 或单节点删除让有子节点的普通节点消失时，操作被拒绝并抖动。
- 显式选中父节点后删除，表示明确删除整棵子树。
- 一次删除多个互不包含的顶层节点时，它们属于同一个删除批次。

## 日期与 Supertag

- 日期不是长期独立的特殊节点种类，而是内置 supertag 或等价元数据提供的能力。
- “今天”是根据日期能力生成的视图，不应成为底层树结构的永久特例。
- 在日期节点上第一次退格会移除日期文本和日期能力，使它成为保留原有子节点的普通节点。
- 再次退格时，它按照普通父节点规则拒绝消失并抖动。
- 当前实现可以暂时保留日期节点类型，但必须保留向 supertag 模型迁移的路径。

## 回收站与恢复

- 回收站按删除的顶层对象展示，子树保持原有层级，不平铺所有后代。
- 同一删除批次可以包含多个互不包含的顶层对象。
- 恢复顶层对象时，其整棵子树一起恢复。
- 恢复优先使用原父节点和原相对位置。
- 原父节点无效、仍在回收站或已永久删除时，恢复到工作区根目录。
- 恢复位置只依赖数据状态，不依赖用户当时位于设置、搜索或其他页面。
- 恢复到根目录后，即使原父节点随后恢复，也不会自动迁回。
- 普通删除只进入回收站；永久删除或清空回收站需要明确确认。
- 清空回收站会永久移除软删除节点、所属字段和折叠状态，必须先保证新快照持久化成功。
- 删除批次应记录原始顶层对象、子树范围和原始位置，不能在恢复时根据当前树猜测。

## 附件

- 节点进入回收站时附件继续保留，恢复后仍可使用。
- 附件文件和节点中的附件引用分离管理。
- 永久删除节点后，只有确认附件未被其他节点引用时才允许清理文件。
- 待删除节点拥有的附件若仍被有效节点通过附件 ID 引用，应转移元数据归属并保留物理文件。

## 当前实现差距

以下规则已经确认，但当前实现尚未完整支持：

- 选择父节点时，界面不一定把所有后代显示为连带选中。
- 日期仍是硬编码节点种类，且日期文本不是普通可编辑内容。
- 合并节点后没有保存身份转向。
- 恢复没有在原父节点无效时回退到工作区根目录。
- 回收站仍未按删除批次和顶层对象组织，因此当前永久清理以所有软删除节点为明确范围。

这些差距应在领域命令和行为测试稳定后逐步处理，不应通过在界面组件中增加特例解决。
