# Markdown 编辑规范

本文定义节点编辑器首轮稳定支持的 Markdown 子集。节点的 `markdown` 字段始终保存用户输入的原始 Markdown；即时预览只负责编辑器内显示，不把 HTML 或渲染结果写入 Store、SQLite 或同步日志。

## 设计边界

- 一个内容节点是一个可独立编辑、拆分、移动和同步的 Markdown 单元。
- 树的父子关系就是列表层级，不再用 `-`、`*` 或 `1.` 建立第二套跨节点列表结构。
- `Enter` 继续拆分节点；粘贴多行文本继续按行创建节点。因此首轮不支持围栏代码块、表格和其他依赖跨行连续文本的块级语法。
- 原始 Markdown 必须可复制、可同步、可回退；即时预览不得改变数据格式。
- HTML、脚注、数学公式、Mermaid 和自定义脚本不在首轮范围内。
- 禁用引用式链接定义 `[标识]: 地址`。节点是独立单元，定义无法可靠服务其他节点，并且会与用户常用的 `[1]:内容` 编号前缀冲突。

## 首轮语法

| 类别 | 语法 | 编辑器表现 |
| --- | --- | --- |
| 粗体 | `**文字**` | 加粗 |
| 斜体 | `*文字*` | 斜体 |
| 删除线 | `~~文字~~` | 删除线 |
| 高亮 | `==文字==` | 背景高亮 |
| 行内代码 | `` `code` `` | 等宽代码样式 |
| 标题 | `# ` 至 `###### ` | 节点级标题样式；H1-H6 均做 Live Preview |
| 引用 | `> 文字` | 节点级引用样式 |
| 待办 | `[ ] 文字`、`[x] 文字` | 可切换的复选框及完成态 |
| 普通链接 | `[文字](地址)` | 完整原子组件；单击显示“打开/修改/删除”，`Ctrl/Cmd+单击`直接打开 |
| 节点链接 | 输入 `[[` 后按标题选择 | 编辑器写入稳定的 `[[node:<id>]]`，显示目标节点标题并可点击进入 |
| 图片 | `![说明](地址)` | HTTP/HTTPS 图片预览；点击打开原地址 |
| 附件 | `[文件](attachment://<id>)`、`![说明](attachment://<id>)` | 已登记附件按类型显示图片、音频、视频、PDF、文本/代码预览或普通文件项 |
| 分隔线 | `---`、`***` | 显示为水平分隔线；光标进入时回显原文 |

粗体、斜体、删除线、高亮和行内代码使用 Markdown 语法树识别。转义字符、未闭合标记、代码内容中的格式字符不能被误渲染。嵌套格式按语法树层级叠加。

## Live Preview 规则

- 行内格式的起止标记（包括粗体、斜体、删除线、高亮和行内代码）默认隐藏，仅保留格式效果；编辑器有焦点且光标或当前文字选区位于整个语法范围内时，显示当前这一组原文。嵌套格式优先显示范围最小的最内层语法。
- 标题与引用前缀默认隐藏；空光标位于标题或引用的整个语法范围内时显示当前前缀。隐藏时连同前缀后的空格一起隐藏，避免内容残留无意义缩进。
- 网页链接、图片和节点链接完成后作为完整组件隐藏控制符；网页链接的空光标仍位于链接源码内部时暂缓组件替换，允许继续输入自动闭合右括号前的地址，光标离开链接后再进入预览。源码模式仍可显示当前节点的完整 Markdown 原文。
- 始终隐藏源码的网页链接、节点链接、图片、附件和待办框作为一个完整的可见内容单元：组件前是其起点，组件后是其终点，从任一外侧边缘都只需一次方向键即可跨过，Backspace/Delete 可整体删除。分隔线保留原始字符位置，不使用替换或原子范围；光标进入时回显 `---`/`***`，可按字符正常移动。
- 网页链接优先在标题前显示网站自身的 `/favicon.ico`，加载失败或邮件地址回退到低强调的地球图标；单击显示“打开 / 修改 / 删除”菜单，菜单打开时允许超出树列表边界显示，关闭后恢复列表裁剪；删除会移除完整链接 Markdown，`Ctrl/Cmd+单击`直接通过安全导航适配器打开。修改表单可更新标题和地址，地址继续执行协议白名单及无协议域名补全规则。
- 外部链接允许 `http:`、`https:` 和 `mailto:`；像 `bilibili.com` 这样的常见域名会按 `https://` 处理。图片仅允许 `http:` 和 `https:`。`javascript:`、`file:`、`data:` 等协议不做预览或打开。
- `attachment://<id>` 只能访问 Store 中已登记的附件；Tauri 图片资源只开放应用附件目录，浏览器沿用当前会话生成的 Blob URL。
- 附件预览按登记的 MIME 类型分类，并在 MIME 缺失或过于宽泛时用常见扩展名补充判断：`image/*` 显示图片，`audio/*` 与常见音频扩展名显示原生音频控件，`video/*` 与常见视频扩展名显示原生视频控件，PDF 使用受控内嵌框查看。浏览器或系统 WebView 是否能解码具体音视频格式仍取决于其原生编解码能力。
- `text/*`、JSON、XML、YAML、SQL、常见源代码与配置文件以只读纯文本预览；内容仅写入 `textContent`，不执行 HTML 或脚本。为避免大文件阻塞编辑器，只内嵌读取不超过 512 KiB 的文本，超限或读取失败时保留系统应用打开入口。
- 压缩包、Office 文档、数据库、可执行文件及其他未归类附件继续显示普通文件项，并交给系统应用打开。音频、视频、PDF 和文本预览也始终保留“打开”入口。
- 图片附件、音频、视频、PDF 和文本预览使用统一标题栏，显示类型图标、文件名、大小、折叠按钮和“打开”入口。点击折叠按钮或标题栏空白区域切换展开状态；媒体控件、预览正文与“打开”按钮不触发折叠。收起时卸载实际预览正文，普通文件项和远程 Markdown 图片不显示折叠按钮。
- 附件折叠状态按“当前节点 ID + 附件 ID”保存在当前设备：同一附件在不同节点中可以分别展开或收起。它是视图偏好，不写入 Markdown、`AttachmentRecord`、操作日志或同步协议，也不作为未来 Supertag/字段的数据属性；新位置默认展开。
- `Ctrl/Cmd+Shift+M` 切换当前编辑器的 Markdown 源码模式，显示全部原始控制符；编辑器失焦后自动恢复 Live Preview。
- 待办在 Live Preview 中始终显示为复选框；源码模式中显示 `[ ]` 或 `[x]` 原文。
- 待办标记显示为可操作复选框；预览态的原子组件覆盖 `[ ]`/`[x]` 及其后置分隔空格，避免光标停在复选框与正文之间；切换复选框只把原文中 `[ ]` 与 `[x]` 的中间字符互换。
- 节点链接不要求用户记忆 ID；输入 `[[` 会按节点标题提供候选，重名节点附带父级路径区分，内部仍保存稳定 ID；预览标题前显示文档图标。
- 未进入视口而未挂载 CodeMirror 的节点仍使用轻量原文占位；首轮不为占位节点建立第二套 HTML 渲染器。

## 格式快捷键

| 功能 | Windows/Linux | macOS |
| --- | --- | --- |
| 粗体 | `Ctrl+B` | `Cmd+B` |
| 斜体 | `Ctrl+I` | `Cmd+I` |
| 删除线 | `Ctrl+Shift+X` | `Cmd+Shift+X` |
| 高亮 | `Ctrl+Shift+H` | `Cmd+Shift+H` |
| 行内代码 | `Ctrl+反引号` | `Cmd+反引号` |
| 切换当前节点源码 | `Ctrl+Shift+M` | `Cmd+Shift+M` |

- 有选区时，快捷键包裹选区。选区已经被同一组标记包裹时，再次触发会移除标记。
- 无选区时，快捷键插入成对标记并把光标置于中间；光标已经位于一对空标记中时，再次触发会移除标记。
- 格式编辑继续进入 CodeMirror 历史，必须可以撤销和重做。

## 与节点编辑的关系

- `Enter`、`Backspace`、`Delete`、`Tab`、`Shift+Tab` 和显式整行删除仍遵循 `docs/编辑规范.md`。
- 普通节点与可编辑页面根节点提供统一的插入/操作菜单；首批菜单直接复用现有 Markdown 命令，包含常用行内格式、标题、引用、待办、分隔线、节点链接和一个“插入文件”动作。菜单分组只用于浏览和搜索，不改变 Markdown 数据格式。
- “插入文件”不按媒体类型拆分按钮，也不设置文件类型白名单；文件选择、多文件选择、剪贴板文件和拖入文件共用同一保存与插入流程，保存后继续由登记 MIME 与扩展名决定预览类型。
- 文件处理期间使用会随 CodeMirror 文档变化映射的临时占位范围；成功项在原意图位置一次写入 Markdown，多个文件保持用户选择顺序。失败不改原选区文本，菜单显示原因并允许只重试失败项。
- 原子组件计入节点内容，组件后的光标不得被判断为节点开头，组件前的光标不得被判断为节点结尾；`Backspace`/`Delete` 紧邻组件时整体删除组件，只有光标确实位于对应的节点外侧边界时才允许跨节点合并。
- 拆分或合并节点时不重写 Markdown；只按现有光标位置拆分或拼接原文。
- 中文输入法组合输入期间不得提前创建节点、重复包裹格式或丢失文本。
- 根视图中的普通内容节点与树内节点共享同一 Markdown 扩展和快捷键。

## Supertag 与后续阶段

内建 `#卡片视图` Supertag 已通过编辑器补全入口支持：选择候选后写入节点元数据，不把标签文字写入 Markdown；具体视图行为见 [`CANVAS_SUPERTAG_SPEC.md`](./CANVAS_SUPERTAG_SPEC.md)。

引用式链接及其 `[标识]: 地址` 定义不纳入支持范围。HTML、脚注、数学公式、Mermaid、自定义脚本、列表、围栏代码块和表格仍不在当前范围内；不能直接信任 Markdown 中的 HTML、本地路径或任意 URL scheme。

后续 Supertag 可继续增加字段和关系，并通过节点字段引用附件、复用同一附件预览组件；字段值仍属于节点模型，二进制附件记录只负责文件身份、存储与校验信息。
